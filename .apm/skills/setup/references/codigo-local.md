# Preparar código local

1. Inspecciona `proyecto.repositorio` y las rutas que el usuario indique. Comprueba existencia, lectura/búsqueda de archivos y que Git reconoce el repositorio; identifica raíz, rama, commit y cambios locales mediante consultas disponibles. La carpeta anfitriona puede ser solo documental. **Salida:** un workspace confirmado o código pendiente.
2. Sin código local ofrece: elegir uno accesible, preparar uno desde un origen real confirmado, continuar solo con documentación o posponer. Para clonar, comprueba origen, referencia, carpeta padre y destino nuevo; muestra la acción antes de ejecutarla. Conserva repositorios y cambios locales existentes. Usa la ayuda real de Git o la operación documentada del entorno; sin terminal da los pasos manuales. La v1 requiere workspace local, no sustituye código por consultas remotas a una API.
3. Comprueba la interfaz de Codegraph y aplica la [validación de workspace/índice/referencia](../../lee-codigo/references/codegraph.md). Identifica proyecto, ruta de índice, fecha, cambios pendientes, discrepancia de worktree y estado del índice, además de la referencia efectiva de Git. **Salida:** correspondencia comprobada o discrepancia concreta.
4. Si falta Codegraph o un índice utilizable, consulta primero versión/ayuda, distribución instalada o documentación oficial accesible. Propón instalación o indexación con comandos y destino verificados y ejecútalos solo si se eligen. No adivines flags ni atribuyas disponibilidad a un registro de instalación. Después vuelve a comprobar identidad y estado del índice y la referencia solicitada. Si se requiere otro workspace o worktree, su preparación también es una acción elegida.

Sin preparación ejecutable, devuelve el paso exacto por realizar y su comprobación posterior. Una referencia no satisfecha o un índice ajeno queda `PENDIENTE`; ofrece documentación independiente en vez de declarar todo el proyecto bloqueado.
